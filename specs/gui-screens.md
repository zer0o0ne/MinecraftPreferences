## Notation
- Frame coordinates: px of the 640×360 frame, origin top-left, $x$ right, $y$ down; rectangle $(x, y, w, h)$ = $[x, x+w) \times [y, y+h)$. Every coordinate in the catalogue is absolute in this frame; texture coordinates $(u, v)$ are in the texture's pixels.
- Class $k$ — a screen layout; its members — the game screens merged into it; window $(x, y, W, H)$ of $k$; `book_panel` — the recipe-book panel rectangle of the recipe-book classes.
- Element — a slot or button of $k$: canonical index $i$, hit rectangle, click point; $n_{max}$ — the largest index over all classes.
- Blit — texture path (relative to `assets/minecraft/textures/`), $u, v, w, h$, destination $(x, y)$.
- $T$ — the needed textures: the set of the textures named by a blit of any member, and `font/ascii.png`, each a path relative to `assets/minecraft/textures/`.
- Dynamic rectangle — a region of a member whose pixels depend on game state or on widget state. Label rectangle — a text label.

## Behaviour
(1) Classes and members (screens not listed are "other"):
| Class | Members |
|---|---|
| `inventory`, `inventory_book` | player inventory, recipe book closed / open |
| `crafting`, `crafting_book` | crafting table, closed / open |
| `furnace`, `furnace_book` | furnace, blast furnace, smoker; closed / open |
| `chest3`, `chest6` | chest, trapped chest, barrel, ender chest, minecart with chest / double chest, double trapped chest |
| `shulker_box` | shulker box |
| `dispenser` | dispenser, dropper |
| `hopper` | hopper, minecart with hopper |
| `brewing_stand`, `enchanting_table`, `grindstone`, `stonecutter`, `loom`, `cartography_table`, `merchant`, `beacon`, `lectern` | one game screen each |
| `anvil` | anvil, smithing table (same slots; the anvil's name field is text input, ignored) |
| `horse` | horse, skeleton horse, zombie horse, donkey, mule, llama, trader llama inventories without a chest |
| `horse_chest3` … `horse_chest15` | llamas and trader llamas with 3, 6, 9, 12, 15 chest slots; donkey and mule with a chest (15) |
| `death`, `sleep`, `pause` | death screen, "Leave Bed" screen, pause menu |

(2) Elements: every slot the player can click and every button; not text fields, not drag-only scroll bars. Hit rectangle = the rectangle tested by the screen's click handler; for a slot at $(x_s, y_s)$: $(x_s - 1, y_s - 1, 18, 18)$ ([G] `ContainerScreen.java:512-521`). A class lists the union of its members' elements and every state-dependent element (recipe-book tabs and recipes, trade offers, beacon powers, enchanting options, disabled horse slots); clicking one that is not shown does nothing.
(3) Canonical index: 1–9 = hotbar slots 0–8, 10–36 = main inventory slots 9–35 (the numbering of the simulator's `info['inventory']`) on every class showing the player inventory; then from 37: container slots in the container's slot order; then buttons by group, groups in the order recipe-book button, recipe-book tabs (top to bottom), recipe-book filter, recipe-book recipes, previous page, next page, enchanting options, trades, stonecutter recipes, loom patterns, beacon primary powers, beacon secondary powers, beacon confirm, beacon cancel, lectern buttons, death buttons, sleep button, pause buttons; row-major within a group. Classes without the player inventory start at 37 too. $n_{max} = 90$ (`chest6`).
(4) Click point = centre of the hit rectangle, $(x + w/2, y + h/2)$.
(5) Drawing data per member, for template construction (block gui-masks): blits as drawn in the normal state (not hovered, not selected, active), in draw order; dynamic rectangles: state-dependent drawings at fixed positions (progress arrows, flames, bubbles, enchanting text, anvil cost, models, previews, recipe-book contents, payment icons), and, for a button whose non-normal drawings (selected, hovered, inactive) extend beyond its hit rectangle, the union of all its drawn rectangles; label rectangles: title and "Inventory" with en_us widths (default container names) and the text colour of the draw call, height 8 without a shadow, 9 with one, 18 for the death title drawn at 2×. A text that varies with game state is not a label: the merchant's title (profession and level) is a dynamic rectangle, the widest of the 66 en_us titles; the death screen's button texts (0xA0A0A0 while the buttons are inactive, then 0xFFFFFF) lie inside their hit rectangles and need no entry. A drawing that lies fully inside an element's hit rectangle, a dynamic rectangle or a label rectangle needs no entry, except a fixed text, which is a label (button texts included). Entries may lie partly outside the window (potion panel, lectern buttons, recipe-book tabs). Slot contents — item icon, durability bar, stack count with its shadow — are drawn within $(x_s, y_s, 17, 18)$, i.e. one row below the slot's hit rectangle; consumers treat that row like the slot (no catalogue entry). Full-screen classes (`death`, `sleep`, `pause`) carry labels and elements only.

## Interface
- Data: `configs/gui-screens.yaml`, generated from [R]'s catalogue and approved with this spec. Top-level keys `classes`, `textures`. Per class: `members` (mapping member → {`blits`, `dynamic`, `labels`}), `description` (one line telling the class apart, for the VLM, Q GX-3), `window`, `book_panel` (recipe-book classes only), `elements`. YAML forms: a rectangle is `[x, y, w, h]`; `window` and `book_panel` are rectangles at class level; dynamic entries are `{name, rect}`; label entries are `{name, rect, color}`, `name` the label's en_us text, `color` its text colour as an integer 0xRRGGBB (a YAML hex literal); elements are `{index, name, kind, hit, click}` with `hit` a rectangle and `click` `[x, y]`; blits are `{texture, u, v, w, h, x, y}`. Entries at every level (classes included) may carry `src`, `note`, `cond` strings, which the loader ignores; an unknown key or a missing required key at any level raises `ValueError`. Unnamed rectangles get the names `window`, `book_panel`, and the element's name for `hit`. `textures`: `url`, `sha1`, `out_dir` (relative to the repository root, resolved against it whatever the working directory), `http_timeout` (s, per phase), `http_retries`, `retry_delay` (s).
- Module `src/mcpref/gui/screens.py`:
  - `@dataclass(frozen=True)` classes: `Rect(name: str, x: int, y: int, w: int, h: int)`; `Blit(texture: str, u: int, v: int, w: int, h: int, x: int, y: int)`; `Element(index: int, name: str, kind: Literal["slot", "button"], hit: Rect, click: tuple[float, float])`; `Label(rect: Rect, color: int)`; `Member(blits: tuple[Blit, ...], dynamic: tuple[Rect, ...], labels: tuple[Label, ...])`; `ScreenClass(name: str, description: str, window: Rect, book_panel: Rect | None, members: Mapping[str, Member], elements: tuple[Element, ...])`.
  - `def load_screens(path: Path) -> dict[str, ScreenClass]` — reads `classes`; checks that every `click` equals (4) for its hit rectangle (else `ValueError`).
  - `def element_at(cls: ScreenClass, x: float, y: float) -> Element | None` — the element whose hit rectangle contains the frame point $(x, y)$; consumers convert recorded mouse positions to frame coordinates first (VPT: $(x/2, y/2)$, Q ACT-16).
  - `def right_handled(e: Element) -> bool` — true iff `e.kind` is `"button"` and its name fully matches `(book_recipe|option|recipe|pattern)_[0-9]+`: the buttons that handle the right mouse button (`specs/action-mask.md`).
- Module `src/mcpref/gui/textures.py`; `@dataclass(frozen=True) class TexturesConfig` (the `textures` keys; `out_dir: Path` already resolved against the repository root, absolute) and `def load_textures_config(path: Path) -> TexturesConfig` (used by consumers to find `out_dir`); `main(argv)` takes the arguments without the program name; `def main(argv: Sequence[str]) -> int`, run as `python -m mcpref.gui.textures configs/gui-screens.yaml`: `make_dirs` (`specs/shards.md`) of the parent directory of every path of $T$ under `out_dir` (a file found there is then trusted durably); the missing ones = the paths of $T$ without a file `out_dir/<path>`, in sorted order; none → does nothing; otherwise downloads `url` into memory (`httpx`, `timeout` per phase; a transport error (any `httpx.TransportError`) or HTTP 5xx retried after `retry_delay` up to `http_retries` times, then exit 1; other non-2xx statuses, redirects included, exit 1 at once; the jar is never written to disk), checks its sha1 against `sha1` (mismatch → exit 1), looks up the member `assets/minecraft/textures/<path>` (exact name) of every missing path before writing anything (the first absent one in sorted order → exit 1, nothing written), then writes each to `out_dir/<path>` by `specs/shards.md` (4); exit 0, or 1 with a one-line message on stderr.
- Datasets (AGENTS.md Code): `{textures.out_dir}/` — item: one texture file of $T$; one file per item, fixed by the format; written by `specs/shards.md` (4) when missing; state: none; a rerun writes only the missing files; read one file at a time by blocks gui-masks, f3-overlay and perception-data. Before the first run of the 2026-10-15 revision the user deletes `out_dir` once (files written earlier were not written atomically).
- Progress bars: none; the loop over the missing paths covers at most 25 small files and ends well under a couple of seconds.

- `scripts/download_data.sh` (block vpt-gui-frames): gains `uv run --locked python -m mcpref.gui.textures configs/gui-screens.yaml` as its first step.
- Data change of 2026-10-14: every label entry gains `color` from its `note` (98 × 0x404040, 12 × 0xFFFFFF, 2 × 0xE0E0E0, the death title 0xFFFFFF); the merchant's title moves from `labels` to `dynamic` of member `merchant`; the labels `Respawn`, `Title Screen` of `death` are deleted (113 labels remain); the colour is dropped from the notes. The catalogue's SHA-256 changes, so the user deletes `data/gui_labels/run.json` once before the next run of `scripts/label_gui_frames.sh` (gui-labels (4)); the labels kept stay valid, since no class description changes ([U] 2026-10-14).
- Produces: the catalogue for gui-labels, gui-masks, env; textures under `out_dir`.
- Tests: hand-checked entries (`inventory` hotbar slot 0: hit (239, 238, 18, 18), click (248, 247); `chest6` index 90 = chest slot 53; `inventory_book` index 47 = the recipe-book button; `beacon` index 42 = primary power "strength"; label colours: `inventory` "Crafting" 0x404040, `beacon` "Primary Power" 0xE0E0E0, `sleep` "Leave Bed" 0xFFFFFF; the merchant's title is dynamic; `death` has no `Respawn` or `Title Screen` label; a label entry without `color` is rejected); no two elements of a class overlap; indices unique, 1–36 the player slots where shown; every click inside its hit rectangle; unknown keys rejected, `src` / `note` / `cond` ignored; `element_at` on rectangle borders (half-open); `textures.py` with a fake HTTP server serving a small zip (sha1 match, mismatch, skip without a request when every file of $T$ is present, retries): exactly the files of $T$ written, byte-identical to the members, nothing else under `out_dir` (no other `gui/` member, no jar); a missing file of $T$ → one download and only the missing files written, the others untouched; a member of $T$ absent from the jar → exit 1 naming the first absent one, nothing written; the parent directories of the present files of $T$ synced before they are trusted; the syncs of `write_file` (as in `specs/shards.md` Tests).

## Out of scope
- Creative-mode screens, books and quills, written books read from the hand, signs, advancements, statistics, chat, options: class "other".
- Text fields, drag-only scroll bars, the recipe-book alternative-recipe pop-up; renamed containers and name-tagged animals (longer titles).
- Cursor-dependent drawings (hover highlights, held item, tooltips), the in-game HUD, the world-dimming gradient and anything outside a class's window: no template data.
- GUI scales other than the frame of [R].
- Every file under `out_dir` not in $T$: left as it is.
- Multiplayer and hardcore play, whose pause and death screens show other texts ("Disconnect", a grey "Open to LAN", "Game Over!").
