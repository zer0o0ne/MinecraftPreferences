## Notation
- $R$ — a producer population. Each record declares `kind` (`targets`, `pretrain`, `mcts`, `rl`, `milestones`), `index` (contiguous nonnegative accepted-record index within `kind`), `id` (arbitrary producer shard/checkpoint/cycle/episode identity) and `context`, a typed `ProducerContext` with exactly `producer`, `split`, `condition`, `model`, `source`, `filters`, `steps`, `cluster_ids`, `artifact_paths`. `condition` is `joint`, `P_only`, `phi_only`, `initial` or `train`/`validation`; conditions are never implicitly pooled. `artifact_paths` is an ordered list of relative POSIX paths, and `context.cluster_ids` is the episode-id list of the complete producer input in row order.
- A record additionally has `populations`: a mapping from every non-Count metric path, including an order/facet suffix where present, to the exact episode-id sequence used by that metric after filtering. Thus vote orders and graph categories never share an implicit cluster alignment. `index.json` preserves this mapping as `clusters`; no numeric conversion of producer `id` is allowed.
- Top-level `joined` contains exact accepted-source payloads, not new metric reductions. An ordinary pretrain record has `joined.outputs` = its exact step `outputs` object and `joined.window_preference` = the closed window's `preference` or null with reason `window_open`. A reference record has `joined.condition` = its exact saved `conditions[condition][split]` object, including late-initial losses. Target records have `joined={}`. Plot paths into these objects start with `joined.`; their nested values are not wrapped as distributions.
- $N(R)$ — row count; $x(R)$ — numerator of a rate, with $0\le x\le N$. `n` means $N$, `numerator` means $x$. A ratio is null when $N=0$ and is never replaced by zero.
- $X_i$ — scalar observation. `Distribution` = `{n, mean, median, quantiles, positive, negative, zero, missing, reason}`. `Rate` = `{n, numerator, value, wilson:{low,high}, bootstrap:{low,high}, insufficient_clusters}`. `Count` = a nonnegative integer. `missing` counts undefined rows and `reason` is null or the exact unavailable reason.
- Quantiles use the linear rule of `specs/pretrain-diagnostics.md` (6): sorted $X_{(1)}\le\dots\le X_{(N)}$, $h=1+q(N-1)$, $j=\lfloor h\rfloor$, $\alpha=h-j$, result $X_{(j)}$ when $\alpha=0$ and $(1-\alpha)X_{(j)}+\alpha X_{(j+1)}$ otherwise. `positive`, `negative`, `zero` are sign fractions.
- $q_a$ — normalized soft next-action target; $\pi_a$ — current full-softmax probability; $\mu_a$ — stored behavior/MCTS visit probability; $C_a$ — previous/current executed-action distribution; $M_a\in\{0,1\}$ — allowed mask. `valid` = rows with $\sum_aq_a>0$; `singleton_teacher` = rows with exactly one $q_a=1$. Zero-target rows are not valid action targets.
- $z_{real}$ — real next latent, $\delta$ — real latent shift, $\widehat\delta$ — predicted shift of the executed root child, $x_v$ — exact predicted state of root child $v$. $Q_\varepsilon$ — MCTS quantisation. Root probabilities include **all** actions: policy prior $p_v$ is the unnormalised prior of each expanded root child, and $\mu_v$ is the full visit-probability vector `Decision.probabilities`, with zero for every unexpanded action.
- $B$ — `bootstrap_samples`; $\ell$ — `ci_level`; $m$ — `min_cluster_count`; $Q$ — `quantiles`; $s$ — `seed`. $E$ — episode-cluster count. $z=\Phi^{-1}((1+\ell)/2)$.
- Cluster mapping: a target pair uses `a.episode`; an unlabeled clip uses its own episode; an RL StepRecord uses `sampling.out_dir#<cycle:06d>`; a History comparison uses the seed's episode (`a.episode`). These mappings are recorded in every record. No independent-pair bootstrap is used.
- Config `configs/diagnostics.yaml` → frozen `DiagnosticsConfig`: `out_dir` (relative non-empty path without `..`), `seed` (`integer` in $[0,2^{32}-1]$), `ci_level` (`number` strictly in $(0,1)$), `bootstrap_samples` (`positive_int`), `min_cluster_count` (`positive_int`), `quantiles` (non-empty distinct `number`s strictly increasing in $(0,1)$, stored as a tuple). Approved starting values: `out_dir=data/diagnostics`, `seed=0`, `bootstrap_samples=1000`, `ci_level=0.95`, `min_cluster_count=20`, `quantiles=[0.05,0.5,0.95]`. Missing/unknown keys and violated constraints raise `ValueError`.

## Math

(1) **Producer-owned observation [U].** Each metric is computed and logged by the producer at its existing event: target provenance during vote/label/graph production, supervised/pretrain metrics on existing diagnostics/reference events, PPO/update/METRA during the corresponding update, MCTS/policy agreement/outcome at completed `StepRecord`, milestones at real action/episode end, and memory at the corresponding sample/cleanup/history event. Producer changes may add observation only; objectives, labels, weights, masks, sampling, MCTS decisions, RNG, environment behavior and updates are unchanged. No new forward/backward pass or rollout is introduced.

(2) **Reduction and zero-support semantics.** Registry entries below produce `Distribution`, `Rate` or `Count`. Macro averages include only classes with $N_a>0$, with class lists stored. `precision_a` is null when predicted support is zero; `recall_a` is null when true support is zero. Infinite logs produce null, never Infinity. Every ratio retains numerator and denominator. Empty-population means/rates are null; a genuine zero event count remains zero.

(3) **Online confidence intervals.** For rate $x/n$, $n>0$, $\hat p=x/n$:
$$c=\frac{\hat p+z^2/(2n)}{1+z^2/n},\qquad d=\frac{z}{1+z^2/n}\sqrt{\frac{\hat p(1-\hat p)+z^2/(4n)}{n}},$$
`wilson={low:max(0,c-d),high:min(1,c+d)}`, with $z=$ `statistics.NormalDist().inv_cdf((1+\ell)/2)`. This is descriptive only; the episode bootstrap is primary.

(4) **Online real-valued cluster bootstrap.** At the close of a producer window (target producer shard, 100 pretrain steps, RL cycle or completed milestone episode), the producer retains typed per-row/group sufficient statistics. With local `numpy.random.Generator(PCG64([seed,5]))`, for replicate $b=1..B$: draw $E$ cluster indices by `choice(E,size=E,replace=True,p=None,axis=0,shuffle=True)`, preserving duplicates and within-cluster row order, and recompute the same reduction from those observations. Replicates use float64 values, not integer-rounded counts. `bootstrap.low/high` are the $(1-\ell)/2$ and $(1+\ell)/2$ quantiles of replicate values. If $E<m$, bounds are null and `insufficient_clusters=true`; raw values and $E$ remain. The plot script never performs this computation.

(5) **Target provenance at producer time.** For retained comparable arcs $C$ and graph-removed arcs $F$:
$$target.graph\_removed=\frac{|F|}{|C|+|F|},\qquad
target.graph\_removed\_all\_pairs=\frac{|F|}{|C|+|F|+|I_{semantic}|},\qquad
target.semantic\_inc=\frac{|I_{semantic}|}{|C|+|F|+|I_{semantic}|},\qquad
target.all\_inc=\frac{|F|+|I_{semantic}|}{|C|+|F|+|I_{semantic}|}.$$
For current train, $C=81430$, $F=23669$, $I_{semantic}=264$ and $N=C+F+I_{semantic}=105363$, exactly as in `data/pair_labels/run.json` and the producer's `categories`/`labels`. One dropped comparison is outside $N$. These give `graph_removed=0.22520670986403296`, `graph_removed_all_pairs=0.22464242665831458`, `semantic_inc=0.002505623416189744` and `all_inc=0.22714805007450434` (numerator $F+I_{semantic}=23933$). `all_inc` and `graph_removed_all_pairs` are distinct series and are never substituted for each other. Producer statuses `dropped`, `invalid`, `no_answer`, `INCOMPARABLE` retain separate names and counts; no `abstain` category is introduced.

(6) **Target comparisons.** `target.vote_lt_0_2` and `target.vote_gt_0_8` use raw valid weighted VLM answers, separately for order 0 and order 1, with strict thresholds. `target.aggregated_gt_0_8` uses corrected preferred-first comparable $p\ge0.5$; `<0.2` is only a contract check. `target.model_lt_0_2` and `target.model_gt_0_8` use $\sigma(s)$ on held-out pairs with the stored oriented target and exact per-pair denominators. These populations are never pooled.

(7) **Corrected pretrain progress.** For fixed population $R$, with optimal constant `p_inc` $t^*$ fitted on global train only:
$$B=2\overline{BCE(t^*,inc)}+2\bar c\log2,\qquad F=2\overline{BCE(t^*,inc)}+\frac{2}{|R|}\sum_{r\in C_R}H(p_r).$$
`pretrain.progress` = $(B-P_R)/(B-F)$, with valid zero-$s$ baseline $B$ and soft-target floor $F$; null when $B=F$ or $P_R$ is absent. It describes total joint P, not isolated `p_succ`; actual `p_inc` may differ. Nonzero constant-$s$ oracles are not model baselines, and exact soft predictions do not imply zero BCE.

(8) **Supervised policy distributions.** On valid rows:
$$policy.nll=-\frac1N\sum_{i,a}q_{i,a}\log\pi_{i,a},\qquad
policy.brier=\frac1N\sum_{i,a}(\pi_{i,a}-q_{i,a})^2.$$
`top1_support` = $\frac1N\sum_i1[q_{i,\arg\max_a\pi_{i,a}}>0]$. `topk_support` = fraction with $\sum_{a\in TopK_i}q_{i,a}>0$, and `topk_target_mass` = $\frac1N\sum_{i,a\in TopK_i}q_{i,a}$. Only $k=1$ and MCTS `width` are defined; ties take the smallest action index. `policy.entropy` and `policy.teacher_entropy` are full-softmax/target entropies. `policy.tv` = $\frac1{2N}\sum_{i,a}|\pi_{i,a}-q_{i,a}|$. `policy.kl_teacher` = $\sum_{i,a}q_{i,a}(\log q_{i,a}-\log\pi_{i,a})/N$; `policy.kl_model` reverses $q$ and $\pi$ and is null if a positive teacher action has zero model probability.

(9) **Hard action errors.** Only on singleton rows, with $y_i=\arg\max_aq_{i,a}$ and $\hat y_i=\arg\max_a\pi_{i,a}$: store full confusion counts. `recall_a` = $TP_a/N_a$ and `precision_a` = $TP_a/N^{pred}_a$. `micro_recall` = $\sum_aTP_a/N$; `macro_recall` and `macro_precision` are unweighted means over classes with $N_a>0$ and $N^{pred}_a>0$ respectively, with class lists stored. Top-k target mass of (8) is not called accuracy.

(10) **Policy baselines.** `uniform_allowed_ce` uses $u_a=M_a/m$ and equals $\log m$ for a normalized teacher on allowed actions. `prior_ce` uses the normalized mean teacher distribution of train valid rows, evaluated on the same population; a positive target action absent from prior support gives null. `copy_ce` uses the approved $r_a=(1-\epsilon_c)C_a+\epsilon_c/|A|$ and exact CE $-\sum_aq_a\log r_a$, with null if any positive $q_a$ has $r_a=0$. No fictitious nonzero constant model is used.

(11) **Mask metrics.** For each state mask $M$: `mask.count` = $|M|$ distribution; `mask.empty` = rate of $|M|=0$; `mask.singleton` = rate of $|M|=1$. `mask.probability` = $1-\sum_{a\in M}\pi_a$. For $Z=\sum_{a\in M}\pi_a>0$, `mask.allowed_entropy` = $-\sum_{a\in M}(\pi_a/Z)\log(\pi_a/Z)$, null when $Z=0$. `mask.executed_violation` = fraction of chosen actions with mask false, using the observed root mask for MCTS and the target state mask $M_{s+1}$ for supervised targets. `singleton_teacher` and `zero_teacher` are separate from mask singleton.

(12) **PPO.** For stored $\rho_t=\pi_t(a_t)/\mu_t(a_t)$ and $A_t$:
- `ppo.ratio`: distribution and max of $\rho_t$;
- `ppo.clip_positive` = rate of $\rho_tA_t\ne\operatorname{clip}(\rho_t)A_t$ among $A_t>0$; `ppo.clip_negative` likewise among $A_t<0$; zero-advantage rows separately;
- `ppo.kl_sample` = $\frac1N\sum_t[\log\mu_t(a_t)-\log\pi_t(a_t)]$;
- `ppo.kl_exact` = $\sum_a\mu_t(a)(\log\mu_t(a)-\log\pi_t(a))$, only where behavior support defines it, with zero-support cases recorded rather than smoothed;
- `ppo.ess` = $(\sum_t\rho_t)^2/\sum_t\rho_t^2$, `ppo.ess_normalized` = ESS/$N$, null when $\sum_t\rho_t^2=0$;
- `ppo.logprob_drift` = mean/median $|\log\mu_t(a_t)-\log\pi_t(a_t)|$;
- `ppo.action_tv` = $\frac12\sum_a|\pi_t(a)-\mu_t(a)|$;
- `ppo.advantage`: mean, std, quantiles and fractions of $A_t>0$, $A_t<0$, $A_t=0$ and $|A_t|$. No advantage normalization exists;
- `ppo.eligible`, `ppo.fresh`, `ppo.pending` = actual index/batch counts and rates, not guessed denominators.
There is no value function or returns/explained variance metric.

(13) **Policy–MCTS agreement.** `mcts.top1_prior_agreement` = rate of $\arg\max_vp_v=\arg\max_v\mu_v$; `mcts.top1_policy_agreement` = rate of $\arg\max_a\pi_a=\arg\max_v\mu_v$. `mcts.rank_prior` and `mcts.rank_visits` are 1-based ranks of the executed action, with ties receiving the smallest rank among equal values. `mcts.policy_support_mass` = $\sum_v\pi(a_v)$. `mcts.kl_prior_visits` = $\sum_vp_v(\log p_v-\log\mu_v)$ when all $\mu_v>0$, otherwise null and separately counted. `mcts.js_prior_visits` uses $m_v=(p_v+\mu_v)/2$ and $\frac12D_{KL}(p\|m)+\frac12D_{KL}(\mu\|m)$, with $0\log0=0$ and remains defined for zero individual priors/visits.

(14) **MCTS realized outcome.** For every StepRecord:
$$mcts.chosen\_hit=\frac1N\sum1[Q_\varepsilon(\widehat\delta-\delta)=0].$$
For the first $k$ children (`1` and MCTS `width`):
$$mcts.topk\_hit=\frac1N\sum1[\exists v\in children_{1..k}:Q_\varepsilon(x_v-z_{real})=0].$$
`mcts.support_hit` uses every expanded child. `mcts.matched_mass` = $\sum_{v:Q_\varepsilon(x_v-z_{real})=0}\mu_v$ per step, reported as a distribution and as unique-mass reliability against empirical hits. Matched mass is computed once per matching child; duplicate matching latents are not double-counted unless they are distinct actions. Exact float equality is not used. `mcts.d_alpha_error` = $d_\alpha(\widehat\delta-\delta)$ and `mcts.zero_shift_error` = $d_\alpha(\delta)$.

(15) **Factual shift and METRA.** `shift.error` = $d_\alpha(\widehat\delta-\delta)$, `shift.error_squared` = its square, and `shift.zero_baseline` = $d_\alpha(\delta)$. `metra.d` = $d_t$, `metra.q` = $q_t$, `metra.lambda` = $\lambda$, `metra.constraint_active` = rate of $1-d_t^2\le\varepsilon$, and `metra.zero_skill` = rate of zero predicted skill. No gradients flow for metrics.

(16) **Exploration, memory and data efficiency.** `mcts.visit_entropy` = $-\sum_v\mu_v\log\mu_v$; `mcts.top_width_prior_mass` = $\sum_{v\in TopWidth}p_v$ before renormalisation. `memory.seeds`, `memory.temporal`, `memory.nearest`, `memory.beam` = counts and rates per real state and per seed. `memory.dedup_ratio` = $1-|\text{unique current comparisons}|/|\text{candidate occurrences}|$, null for zero occurrences. `memory.repeated_comparison` = rate of comparisons already present in an older History. `memory.capacity` = vertices/capacity, `memory.evictions`, `memory.unused`, `memory.empty_candidates`, and `memory.episode_coverage` = episodes with at least one current History vertex / all episodes. Metrics separately name `all_real_states`, `selected_seeds`, `temporal`, `nearest` and `beam` populations.

(17) **Inventory milestones.** For each milestone $m$ in $\{\text{stone pickaxe, iron, iron pickaxe, diamonds, obsidian, blaze rod}\}$, define $t_{e,m}$ as the first real action index whose inventory contains the mapped item. Mappings are exactly `stone_pickaxe`; `iron_ingot`, `iron_ore`, `raw_iron`; `iron_pickaxe`; `diamond`; `obsidian`; `blaze_rod`. `milestones.coverage_m` = reached episodes/all recorded episodes, with (3)–(4). `milestones.time_to_first_m` = median and quantiles of $t_{e,m}$ among reached episodes only. Unreached episodes are right-censored at the last recorded action and enter a Kaplan–Meier curve $\hat S_m(t)$, not the mean time-to-first. A joint record stores the first-time vector and order relations, not repeat pickups. Nether/dimension milestones and cumulative mining stats are excluded.

(18) **Update health.** For every already existing backward/update: global and per-group preclip norms, clip coefficient, nonfinite counts, active flags, actual update norms and LR/schedule position. For `pi.head.weight`, `update.head_row_norm` = per-action row norms of the existing gradient and update. `update.zero_gradient_row` = rate of zero rows, `update.unsupported_action` = rate of actions with no valid teacher rows, and their intersection, distinguishing data absence from optimization absence. `update.logit_norm` stores quantiles of existing logits. `update.unavailable` is null only for the existing `zero_decay_factor` case; no placeholder tensor is created.

### Stage 33a — target provenance, pretrain, shared artifacts and preference plots
- `src/mcpref/diagnostics/targets.py`:

  - `def on_label_shard(labels: Sequence[dict], *, cfg: DiagnosticsConfig, context: ProducerContext) -> MetricRecord` — called when an acyclic label shard completes, using the corrected `pairs.json`, never the raw vote shard.
  - `def on_graph(comparisons: Sequence[dict], *, categories: Sequence[str], cfg: DiagnosticsConfig, context: ProducerContext) -> MetricRecord` — called when graph correction completes. `len(categories)==len(comparisons)` and every category is exactly `comparable`, `removed`, `incomparable` or `dropped`; `categories[i]` describes the original `comparisons[i]`, including dropped rows. `preferences.acyclic.shard_pairs` returns these already computed categories as a third result, so Eades and verdicts are never repeated. Each graph ratio has its own aligned `populations` entry.
- `src/mcpref/pretrain/diagnostics.py`:
  - `def on_pretrain_step(rows: PreferenceRows | None, *, fit: GlobalFit, cfg: DiagnosticsConfig, context: ProducerContext) -> MetricRecord` — (7), using per-step preference rows and the `GlobalFit` created once by the existing initialization/resume lifecycle. `context.split="train"`, `context.condition="joint"` and `context.steps==(step,)`; `rows=None` is an empty pair population, not a zero loss. There is no new evaluation.
  - `def on_reference(rows: PreferenceRows | None, *, pairs: Sequence[ReferencePair] | None, cfg: DiagnosticsConfig, context: ProducerContext) -> MetricRecord` — consumes the existing reference forward's per-split rows and typed pairs. The caller filters pairs to `context.split` through `selection.items[pair.micro_batch].part`. For late `initial`, `rows=None` and aggregate metrics come only from the saved initial condition. `pairs=None` is the legacy metrics-only mode. `delta_joint` occurs only in `joint`; `delta_only_phi` only in `phi_only`; other conditions use reason `not_applicable_condition`. Applicable deltas in legacy mode use `legacy_reference_pairs_absent`. There is no new evaluation or backfill.
- `@dataclass(frozen=True) class ReferencePair`: fields `micro_batch: int`, `pair_in_micro: int`, `a: str`, `b: str`, `labels: dict`, `baseline: float`, `only_phi_post: float`, `joint_post: float`, `delta_only_phi: float`, `delta_joint: float`. `micro_batch` is the zero-based fixed-reference evaluation micro-batch index and `pair_in_micro` is the zero-based pair position inside it. Fields remain non-nullable.
- Reference layout is fixed for a whole run by shard 0. A new shard 0 contains `metrics.json` and `pairs.json`, and every later shard contains both. ### Merge/artifact schema and resume
- `run.json`: `{config,sha256:{config,inputs},channels,complete,counts}`. `channels` has an independent entry for every event-matrix channel: `{watermark,next,events,records,complete}`. `sha256.inputs` is a mapping from channel to the digest of its ordered relative POSIX source path + NUL + bytes, appended only when that source event is consumed; mutable producer run files are not content-fingerprinted. A config or retained-input identity mismatch is an error.
- The first instrumented run writes each channel watermark before producing a record: target `next=complete_shards(source)`; ordinary pretrain `next=restored_step+1`; reference `next=complete_shards(reference)`. Consequently an already accepted historical source event is never backfilled, while a missing latest reference due at the restored state is still evaluated normally. Later producer appends extend only the corresponding channel. A channel is complete when its source run is complete and every event at or after its watermark is accepted; global `complete=true` requires every registered 33a channel complete and a current `index.json`. `counts` maps every channel to `{events,records}`.
- `{out_dir}/<kind>/<name(k)>/metrics.json`: exactly one `{version:1,kind,index,id,context,populations,metrics,joined}` record. `index==k`; `id` remains the event identity of the matrix. `context` is the exact `ProducerContext` of Notation. Every metric is the registry's `Rate`, `Distribution` or `Count`; missing values are null with reason. There is no packed record list and no `items_per_shard` setting.
- Before publishing a source shard/checkpoint/reference shard, its producer atomically writes `{out_dir}/outbox/<channel>/<name(event_ordinal)>.json` = `{version:1,channel,event,source,record}` with pending `record.index=null`. After source publication, the producer applies the exact accepted-source join and atomically calls `write_record`; it then updates `run.json` and removes the outbox entry. If the source is absent on resume, its pending outbox is discarded and the ordinary producer recomputes the event. If the source is accepted, the persisted outbox is joined and published without a model pass or producer recomputation; an already accepted matching event `id` is not written twice. Completed records are never rewritten.
- `summary.json` is not an offline metric recomputation. `index.json` is only `{version:1,records:[{kind,index,id,path,condition,clusters}],plots:[{group,file,series,x}]}` generated from accepted records and actual plot facets. Record `path` uses `index`, never `id`. No offline orchestrator or old-log summary is used.
- Resume checks all reference shards for a consistent legacy/new layout, retains complete diagnostic records, validates channel identities, recovers only outboxes whose source is accepted, continues at each channel's `next`, and regenerates `index.json`. A partial event has no accepted record. Source shards are read one at a time; memory holds only one producer event and its pending record, not an output dataset.
- Progress bars on stderr with no postfix: `diagnostics targets` (unit `shard`), `diagnostics pretrain` (unit `step`), `diagnostics rl` (unit `cycle`), `diagnostics mcts` (unit `step_record`), `diagnostics milestones` (unit `episode`), `diagnostics plot` (unit `group`). Target work advances after the vote shard or both acyclic records are accepted; pretrain advances after an ordinary step's record or all eight reference records are accepted. Totals include only events at/after watermarks, initial counts come from per-channel accepted events, and bars advance only on accepted source events. No remaining work prints `<desc>: nothing to do`; all work previously complete prints `<desc>: already done`.

## Plot registry

The plot entry point consumes only accepted records. It does not average window values again. All reductions, confidence intervals and summary values already exist in records. For plot lookup only, `preference.<path>` resolves to `joined.window_preference.<path>` in an ordinary-step record and to `joined.condition.preference.<path>` in a reference record; this is a source alias, not a metric key or reaggregation. The registry is the single source of each full relative filename, including its group prefix and `.svg`; writer and `index.json` use the same entry. Only actually written split/condition facets are indexed, not every theoretical combination. Filenames are deterministic and written atomically using `<name>.part` followed by rename; a cheap replot overwrites existing plots and requires no resume. Every group has separate train/validation and joint/P_only/phi_only facets where applicable. No double y-axes and no implicit scale hiding: losses share a panel only when their units and population match; rates share only when their denominator matches; incompatible units/populations use facets or separate files.
