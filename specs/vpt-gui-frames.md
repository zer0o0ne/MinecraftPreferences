## Notation
- Subsets $S$: the keys of config `index_urls`, in config order (`6xx`, `7xx`, `8xx`, `9xx`, `10xx`).
- Episode $e$: a relpath of $S$'s index; version $v_e$ = the `<version>` path component, compared as a tuple of integers.
- $\ell_0, \dots, \ell_{n-1}$ — the lines of $e$'s `.jsonl`; frame $i$ is paired with $\ell_i$.
- $F_e$ — eligible frames, ascending; $r$ — frames taken from $e$.
- $N$, $m$ — total frames and frames per episode (config).
- Draw — one iteration of the outer loop of (3): a subset chosen, its episodes popped until one is valid or its pool is empty, and for a valid episode the choice of its frames; $K$ — draws per plan shard (config); $h$ — complete plan shards.
- $L$ — size in bytes of a file fetched by (f); $q$ — threads of (f) (config), $1 \le q \le 20$; $p = \lceil L / q \rceil$ — part size, so a file of $L > 0$ bytes takes $\lceil L / p \rceil \le q$ range requests.
- $t_i$ — seek time of frame $i$; $Y, U, V$ — luma and the two chroma planes ($U = C_b$, $V = C_r$); $R, G, B$ — the RGB view.
- Config `configs/vpt-gui-frames.yaml` → `@dataclass(frozen=True) class GuiFramesConfig`: `index_urls` (mapping subset → URL), `x_ms_version`, `min_version`, `required_options` (mapping option → value), `width`, `height`, `fps`, `n_frames` ($N$), `per_episode` ($m$), `seed`, `workers`, `fetch_streams` ($q$), `plan_shard_draws` ($K$), `http_timeout` (s, per connect / read / write / pool phase), `http_retries`, `retry_delay` (s), `ffmpeg` (program path), `ffmpeg_rw_timeout` (s), `ffmpeg_timeout` (s), `verify_relpath`, `verify_frames` (list of $i$), `out_dir` (relative to the repository root).

## Domain
- $N \ge 1$, $K \ge 1$, at least one subset; no relpath listed by two subsets ([R3]); not checked at load.
- `{out_dir}` holds only what this block writes.

## Math
(1) $F_e = \{ i : 1 \le i \le n - 1,\ \ell_i.\text{isGuiOpen} \wedge \ell_{i-1}.\text{isGuiOpen} \}$ — the GUI is drawn in frame $i$ for every screen type ([R], containers one tick late).
(2) Episode reason, checks in this order, the first failing one is the reason, `None` if all pass: `version` ($v_e <$ `min_version`; decided from the relpath, nothing downloaded); `missing` (HTTP 404 for the `-options.json` or the `.jsonl`); `empty` (either file has zero bytes); `malformed` (either file is not valid JSON / JSON Lines); `options` (some `required_options` key differs from the options file); `no_gui` ($F_e = \emptyset$). The `.mp4` is not checked ([R]: it is empty only with an empty `.jsonl`).
(3) Plan, one `numpy.random.Generator(PCG64(seed))` used only here, sequentially, until $N$ frames are planned or every pool is empty: pools = each subset's relpaths in index order with exact repeats removed; $s$ = `rng.integers(len(active))` over the subsets whose pool is non-empty, in config order; then within subset $s$, repeat: $j$ = `rng.integers(len(pool))`, `e = pool.pop(j)`, compute the reason (2), until an episode is valid or the pool is empty (an empty pool drops $s$ from the active subsets); for a valid $e$: $r = \min(m, |F_e|, N - \text{planned})$, frames = `rng.choice(F_e, size=r, replace=False)` in draw order.
(3') Plan shards ([U] 2026-10-15): the draws of (3) are cut into consecutive shards of $K$ draws, the last one shorter when (3) ends; every shard holds at least one draw (no shard is written when (3) ends on a shard boundary or makes no draw); a shard holds its draws' episode records and frames and the generator's `bit_generator.state` after its last draw. Continuation from $h \ge 1$ complete shards: the generator state is set to that of shard $h - 1$; each subset's pool is its initial pool of (3) without the relpaths of that subset's records in the $h$ shards, its order kept; planned = their frames; (3) goes on (ending at once when $N$ frames are planned or every pool is empty), its next draw starting shard $h$. With $h = 0$, (3) starts from `seed`. The records and frames of all shards, concatenated in shard order, equal those of (3) run without interruption, for any interruption points and any $K$ of each run.
(4) $t_i$ = `"%d.%02d" % (i // fps, (100 // fps) * (i % fps))` for `fps` = 20 ([R]).
(5) RGB view of a raw frame (planes $Y$: height × width, then $U$, $V$: height/2 × width/2), [BT601] limited range with chroma repeated over its 2 × 2 block, in float64:
$R = \frac{255}{219}(Y - 16) + \frac{255}{224} \cdot 1.402\,(V - 128)$,
$G = \frac{255}{219}(Y - 16) - \frac{255}{224} \cdot \frac{1.402 \cdot 0.299}{0.587}(V - 128) - \frac{255}{224} \cdot \frac{1.772 \cdot 0.114}{0.587}(U - 128)$,
$B = \frac{255}{219}(Y - 16) + \frac{255}{224} \cdot 1.772\,(U - 128)$,
each value $x \mapsto \min(255, \max(0, \lfloor x + 0.5 \rfloor))$ as `uint8`.

## Behaviour
- Retries (every HTTP request of (a), (e), (f)): any `httpx.TransportError` (timeouts, connection and protocol errors, e.g. a body cut short) or HTTP 5xx is retried after `retry_delay` up to `http_retries` times, then aborts the run (so the plan never depends on network luck); each request has its own retries.
- (a) Indices: `make_dirs` (`specs/shards.md`) of `{out_dir}/indices/`; then, in config order: `{out_dir}/indices/<subset>.json` present → used as it is; otherwise the index URL is downloaded with one `GET` (any HTTP failure after the retries aborts the run) and its body written there by `specs/shards.md` (4).
- (b) Plan (3), (3'): `run` passes `plan` the directory `{out_dir}/plan/` and a `fetch` that answers the `index_urls` with the files of (a) and every other URL (the options and `.jsonl` files) by the ranged fetch (f); a missing file → reason `missing`. `plan` reads the complete shards one at a time (`specs/shards.md` (2)) to continue (3'), then writes each new shard by `specs/shards.md` (1) as soon as its $K$ draws are done (the last one when (3) ends); memory holds the shard in work and the state needed to continue: the generator, the counts, and the pools (the indices' relpaths), built once — the relpaths drawn in the complete shards are collected per subset while those shards are read, then removed from the pools at once; never the frames or records of other shards.
- (c) Extraction, after the plan: `make_dirs` (`specs/shards.md`) of `{out_dir}/frames/`, in every run, before the `extract` total (below) is counted; (c) is skipped when that total is 0; the plan shards are read one at a time in order; the frames of a shard without `<id>.yuv` are extracted on `workers` threads, and the next shard is read once each of them has a result; a frame's video URL = the `basedir` of `indices/<subset>.json` + its `relpath`; a frame: `ffmpeg_command` writes to `<id>.yuv.part`; success = exit code 0 and exactly width × height × 3 / 2 bytes, then the file is published as `<id>.yuv` by `specs/shards.md` (3); otherwise retried after `retry_delay` up to `http_retries` times, then the frame's status is `failed`; a run of ffmpeg longer than `ffmpeg_timeout` counts as a failure.
- `run.json` is written by `specs/shards.md` (4) at the start of every `run` command, after the rerun check of (d) and before (a): `{"config": <this run's config as loaded>}`; at the end of a run that completes it is rewritten the same way with the counts added: `episodes` as returned by `plan`; `frames`: `failed` = the frames of this run's (c) whose status is `failed`, `ok` = the planned frames minus `failed`. The outputs are complete when `run.json` holds the counts.
- (d) Rerun: if `run.json` exists and any of the output fields `index_urls`, `min_version`, `required_options`, `width`, `height`, `fps`, `n_frames`, `per_episode`, `seed` differs from its config, compared as JSON text (`json.dumps` of each value, so the order of `index_urls` and of `required_options` counts) → abort; the other fields may differ between runs. Otherwise: the stored indices are used (a), the plan continues after its complete shards (3'), frames whose `.yuv` exists are skipped and the others (never tried or `failed`) are extracted. Starting over = deleting `{out_dir}`.
- (e) `verify` (run by `download_data.sh` before the full run, VF-2): downloads the whole `verify_relpath` video with one `GET` (URL: the `basedir` of the first index, in config order, that lists it; none → abort) into a temporary file, decodes it sequentially with the same ffmpeg to raw yuv420p, extracts each of `verify_frames` with the extraction of (c) (`ffmpeg_command`, retries, `ffmpeg_timeout`, `.part` and size check; a frame still failing aborts), and aborts unless every one equals the sequential decode byte for byte; the temporary files are deleted; `verify` writes nothing under `{out_dir}`.
- (f) Ranged fetch of one file URL (header `x-ms-version` on every request): `HEAD` → 404: the file is missing (`None`); any other status but 200, or a 200 without `Content-Length`, aborts the run; $L$ = its `Content-Length`. $L = 0$ → the empty file, no further request. Otherwise parts $j = 0, \dots, \lceil L / p \rceil - 1$ are bytes $[jp, \min((j+1)p, L) - 1]$, each one `GET` with header `Range: bytes=<first>-<last>`, all started at once on $q$ threads; a part must answer 206 with exactly $last - first + 1$ bytes, otherwise the run aborts; the file = the parts concatenated in order. When parts fail, the run aborts once every part has finished (each with its own retries), with the failure of the lowest failing $j$.

## Interface
- Module `src/mcpref/vpt/gui_frames.py`; `def main(argv: Sequence[str]) -> int`, run as `python -m mcpref.vpt.gui_frames {verify|run} <config path>`; exit 0 on success (failed frames counted, not fatal), 1 on abort with a one-line message as the last line of stderr; progress bars on stderr (below).
  - `def load_config(path: Path) -> GuiFramesConfig`.
  - `def eligible_frames(lines: Sequence[Mapping]) -> list[int]` — (1).
  - `def version_ok(version: str, min_version: str) -> bool`; `def options_ok(options: Mapping, required: Mapping) -> bool` — parts of (2).
  - `def plan(cfg: GuiFramesConfig, fetch: Callable[[str], bytes | None], directory: Path) -> tuple[int, Counter]` — (3), (3'): continues the plan from the complete shards of `directory` and writes the rest there; returns the frames planned over all shards and the count of episodes per reason (`None` for valid ones) over all shards; `fetch` returns `None` for 404.
  - `def fetch(client: httpx.Client, cfg: GuiFramesConfig, url: str) -> bytes | None` — (f); `None` for a missing file; `client` carries the header `x-ms-version`.
  - `def frame_time(i: int, fps: int) -> str` — (4).

## Out of scope
- Recorder versions < 6.12, other window sizes, GUI scales, languages, resource packs; option changes in the middle of an episode (the options file is one snapshot); BASALT data.
- Whole-video downloads (except `verify`); caching `.jsonl` files.

- A file changing between its `HEAD` and its parts (the data are static; the indices are fixed on disk at their first download); files served with a `Content-Encoding` ([R2]: none); ranged fetch of the indices (a) and of the `verify` video (e); interruption by Ctrl-C (Python's default, as in (c)).
- Checking each video's frame rate and frame count (accepted from [R]).
